- (decision) Scope is repo HEAD only, not the live deployment: Dmitry chose to handle deploys himself, so no hosting or workflow config changes are in this spec.

- (note) Live echowaves.com serves 5 script tags on / while HEAD ships zero JS, so the deployed site predates the JS-free rebuild; audit findings may describe CSS that no longer exists.
- (capability) CAP-1 agents can discover and verify the site's resources through a machine-readable catalog that Lighthouse's ARD audit parses as valid JSON.
- (capability) CAP-2 agents reading llms.txt get a standards-shaped file with an H1, a summary and links to the site's real pages.
- (capability) CAP-3 every resource named in llms.txt and the catalog is one the build actually produced, so agents are not sent to paths that do not exist.
- (capability) CAP-4 every text role on every surface meets WCAG AA 4.5:1 in all eight palettes, with the hero panel role measured by an automated gate.
- (capability) CAP-5 npm run verify rejects missing, malformed or stale agent-discovery artifacts alongside its existing content gates.
- (constraint) No deployment, hosting, or server/header configuration changes: Dmitry deploys himself. Artifacts must be static files the Astro build emits into dist/.
- (constraint) The site ships zero JavaScript and stays that way; agent discovery is static files plus markup, never a client-side manifest generator.
- (constraint) ARD catalog entries must be valid against ARD spec v1.0: specVersion + entries[] required, each entry an urn:air:{publisher}:{namespace}:{name} with type and exactly one of url or data.
- (constraint) llms.txt follows llms.txt.org order (H1, blockquote summary, optional detail, ## File Structure) and satisfies Lighthouse's checks: at least one H1 and at least one link.
- (constraint) Catalog entries cite only resources whose URLs come from src/data modules the verify gate already scans; no hand-typed URLs.
- (assumption) Serving both /.well-known/ard.json (what Lighthouse probes) and /.well-known/ai-catalog.json (ARD spec v1.0 WELL_KNOWN_PATH), identical content, plus a <link rel> in HTML, rather than betting on one name.
- (assumption) The contrast failure belongs to the deployed CSS, not HEAD: all eight palettes measure >=4.5:1 for every text role at HEAD, and .man-body copy on --panel-raised is 4.55:1 at its worst (Dracula).
- (assumption) The stale review-accessibility.md note about eleven sub-AA ratios in published palettes is superseded by commit 6c0c34d, which nudged every palette's text roles to AA.
